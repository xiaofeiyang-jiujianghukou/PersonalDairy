# 设计文档:产品愿景与关键决策

## 一、这是什么

一本**只属于一个人的私人日记**。它和 Halo / 有道云笔记的本质区别在于:

- 那些是「知识库 / 笔记系统」,鼓励你建立结构、分类、目录;
- 这本是「时间流」,你只管记录,结构由时间自动生成。

## 二、核心诉求(来自用户原话的提炼)

1. 记录零负担:不建目录、不打分、不分类,打开就写。
2. 按时间回看:哪天记了什么、上个月发生了什么、这个月过得怎么样。
3. 被动情绪感知:AI 从文字里自动归纳「心理状况、生活和工作状况」,用户不额外操作。
4. 越记越懂我:未来能在我需要时安慰、开导我。
5. **隐私是底线**:数据本地、只属于自己、不分享;多端同步是「授权 + 端到端加密」,且同步后数据仍以加密态落在本地(像微信一样"数据在自己手里")。

## 三、关键决策与理由

### 1. 本地优先 + 每用户数据隔离
每个人一份独立的 SQLite 库,互不共享、互不搜索。这带来两个直接好处:
- **隐私**:数据物理隔离,天然没有"服务器集中存储所有人日记"的风险。
- **性能**:无论用户量多大,单次搜索的体量始终是"一个人的一生日记"(十年 ≈ 几千条),永远瞬间返回。

### 2. 搜索用 LIKE 而非 FTS5(已与用户确认)
- 个人日记体量极小(每天 1–2 篇,十年约 7300 篇、十几 MB 文本)。
- SQLite 的 LIKE 扫描在内存里每秒可扫数 GB,这个量级几毫秒即返回,永不会成为瓶颈。
- FTS5 对中文按字切分、需维护同步索引,属于当前阶段的过度设计。
- **升级路径**:若未来出现"极端高产用户"或需要"相关度排序 / 输入即时高亮"等进阶搜索体验,再引入 FTS5,只需改 `db.ts` 一处。

### 3. AI 可插拔 + 供应商无关
- 情绪小结、未来的陪伴对话,都只依赖一个 `AiProvider` 接口(`chat(messages)`).
- 默认实现 `OpenAICompatibleProvider` 覆盖豆包 / DeepSeek / 通义 Qwen / 本地 Ollama,
  只需换 `baseUrl + key + model`,业务零改动。
- 无密钥时降级为 `NullProvider`,保证产品其余功能不受影响。
- **混合模型**:日记含图片时自动用视觉模型(看图),纯文字时用文本模型(质量最高)。
- 未来隐私升级:可无缝换成**本地模型**,日记完全不出本机。

### 4. 存储用 Node 内置 sqlite(零原生依赖)
- 避免了 better-sqlite3 这类原生模块的编译/移植负担,安装即用。
- SQLite 文件即数据库,天然满足"可迁移、可备份"。

### 5. 数据在代码之外 + Markdown 逃生门
- 数据目录默认 `~/.local/share/personal-diary`,与代码仓库分离,升级不丢数据。
- 一键导出 Markdown / JSON,保证用户**永远不被锁死**,随时能把日记带走。

## 四、分期

| 阶段 | 内容 | 状态 |
|---|---|---|
| v1 | 单机日记 + 时间轴/日历 + 月度情绪小结 + 搜索 + 导出 | 当前 |
| v2 | AI 陪伴对话(基于全部记录,可安慰开导) | 待定 |
| v3 | 移动端(PWA → 原生 App) | 待定 |
| v4 | 多端端到端加密同步(授权后开启) | 待定 |

## 五、扩展点(为将来预留的接缝)

- `AiProvider` 接口 → 换模型 / 换本地模型
- `db.ts` 的搜索函数 → 升级 FTS5
- 存储层 → 加字段级加密(当前明文存储,后续可加口令加密)
- `packages/shared` 的类型契约 → 同步 / 移动端复用同一套 API 契约
